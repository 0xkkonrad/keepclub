Already decided — not up for debate (scope doc + today's brief)
  • One app, courses inside: Competent Crew's deck was built content-only because the shell is Munin's job — the course picker in front is settled, this page decides its shape.
  • The engine is Day Skipper's, extracted (Phase 0): PWA shell, review loop, lightbox, figures renderer, sync, tests come across; Day Skipper keeps working throughout and becomes the first course.
  • The layering (Konrad, 27 Jul): munin = infra with the themes engine · courses = colour + thematic doodles + loading screen + other thematic elements · cards = content, with tags/categories at the engine level.
  • A course theme = accent pair (light+dark) + doodle set + section art + loading screen. Nothing else varies. Type, layout, grade flags, flag yellow, review UX are Munin, shared by every course. The loading screen is a first-class slot: boot art, its animation and its line ("Loading deck…" + the rocking boat is Day Skipper's; the raven default gets its own).
  • Theme files are never cross-linked (Konrad, 27 Jul): every course folder is self-contained. When two courses use the same drawing it is a copy that happens to coincide, not a shared import — Competent Crew's colour-only reskin still ships its own doodle files.
  • Cards: the engine eats Day Skipper's cards.json format — the Competent Crew build already emits it.
  • Default theme is the raven: your-own-import decks get Munin's accent + raven doodle set (crow's-feet progress prints, the hoard for badges) — cute and doodly, per the scope doc's corvid table, not epic.
  • First run = the course shelf. No tour, no account — sign-in only ever turns on sync.
  • Lowercase chrome, never card content — inherited as-is.
  • Name check: repo and scope say Munin (Odin's memory raven); the brief spelled it "mumin" — read as a typo. Shout if the Moomin spelling was actually intended (it's also a live trademark).
